# 简历生成提示词

以下提示词用于让 AI 基于项目源码和文档生成一份面向面试官的简历。直接复制粘贴，替换项目名即可使用。

---

## 提示词

```
你是一位资深技术简历顾问。请扫描我的项目代码和文档，生成一份面向后端/算法面试官的简历。

## 你的读者
面试官，没有看过你的源码。他只有 30 秒扫读简历，然后决定是否追问。他关心的不是"你用了什么技术栈"，而是"你解决了什么难题、你的决策聪明在哪"。

## 输出格式

**项目名 · 角色**
技术栈：（一行，不分类别，只列关键技术）

项目简介：（3 行以内，覆盖：项目定位、背景、后端做了什么、支持什么场景）

功能描述：（6 条，每条 2-3 行）

## 写作原则

### 1. 禁止出现的东西
- 源码文件路径（如 "contracts/sse-events.schema.json"）——面试官看不到源码
- 内部函数名、类名（如 "PipelineStages"、"StreamContext"）——除非是业界通用术语
- 破折号（——）密集出现——像机器生成的
- 带冒号的总括句（如 "投机检索：利用意图阶段..."）——每条直接从具体内容开始
- 防御性表述（如 "不用 LangChain"）——好的设计不需要靠否定别人来证明
- AI 味的过渡词（"这层解决的核心问题是""值得一提的是""另外"）

### 2. 每条功能描述的结构
不要说"我做了 X"，要说"遇到 Y 问题，选了 Z 方案，因为 W"。

- 开头：直接进入具体做法或遇到的问题
- 中间：关键的取舍理由，用具体例子说明（如 "避免 200 元预算被语义漂移到 198 元商品"）
- 结尾：量化结果或兜底策略（如 "实测从 7s 降到 3s""失败时自动回退串行"）

### 3. 数字怎么用
- 数字必须来自代码中可验证的实测数据，不编造
- 数字放在句末或显眼位置，不做 punch line 就不要写
- 如果某个数字样本量太小（如 20 条样本的评测分数），不写裸数字，改写能力描述

### 4. 技术名词怎么用
- 只保留面试官能懂的：pgvector、BM25、SSE、asyncio、PostgreSQL
- 面试官需要翻源码才能懂的删掉：RRF、Cross-encoder、weakref.finalize、HNSW
- 如果某个技术的价值在于"为什么用它"而非"它是什么"，写理由不写名字

### 5. 语言质感
- 像在和后端同事讨论技术方案，不像在写技术博客
- 例子优先于抽象描述："向量理解'油皮→控油'这类隐含关联" 优于 "向量召回做语义匹配"
- 短句优先。一句话说不清就拆成两句

### 6. 压缩标准
- 写完之后检查：每条能不能在 A4 纸上不超过 3 行（约 80-100 字）
- 删解释，留结论。删因果铺垫，留动作和理由。
- 如果发现自己在解释"为什么这个技术存在"，删掉。如果发现自己在解释"为什么我选择这个技术而不是另一个"，保留。

## 生成步骤

1. 先扫描项目的核心代码和文档，提取所有可能写进简历的技术点
2. 按"面试官会追问的程度"排序，选出 6 个最有区分度的
3. 6 个点覆盖 6 个维度：架构设计、性能优化、核心能力、质量保障、传输可靠性、状态管理
4. 按上述原则写成 6 条功能描述
5. 反复压缩，直到每条 2-3 行

## 配套产出

简历写完后，为每条功能描述生成面试准备材料，包含：
- 功能的业务背景（为什么需要这个设计）
- 详细技术讲解
- 精确的源码位置（文件 + 函数 + 行号，用于面试前复习）
- 每个点 2-4 个面试追问 + 参考回答
```

---

## 使用方式

将上面的提示词发给 AI，替换"我的项目"为你的项目路径或描述，即可生成同等质量的简历和面试准备文档。

## 这份简历风格的形成过程（供参考）

这份提示词是经过十几轮"写→锐评→改"迭代后收敛出来的。核心教训：

1. **不要写给看得见源码的人看。** 一开始的简历引用了 `contracts/sse-events.schema.json`、`weakref.finalize`，读起来像技术笔记。面试官没看过代码，这些引用是噪音。

2. **每条讲一个决策故事。** 不是"我用了 SQL 硬过滤 + pgvector + BM25 + RRF + Rerank"，而是"语义检索分不清 200 元和 198 元，所以外层先用 SQL 卡住刚性条件"。前者是功能列表，后者是工程判断。

3. **AI 味来自过度结构化。** 破折号、冒号总括句、"第一层/第二层/第三层"编号体，读起来像机器写的。删掉这些，句子变短，节奏变自然。

4. **压缩比写更重要。** 初版每条 5-6 行，终版 2-3 行。删的不是技术含量，是解释性包袱。面试官追问时你再展开讲，简历只需要让他想追问。

5. **诚实比炫技更重要。** 样本量小就说样本量小，不要编数据。延迟数字标注"实测"。没用过的技术不写，用过的写清楚取舍理由。
