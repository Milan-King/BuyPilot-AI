BuyPilot-AI · 后端核心开发
技术栈：Python FastAPI + PostgreSQL/pgvector + asyncio + SSE + 百炼 Qwen / Doubao + jieba + BM25 + Docker Compose

项目简介：基于 RAG 的多模态电商智能导购 Agent，字节跳动 AI 全栈挑战赛参赛项目（3 周 / 3 人）。
后端自建 Agent 管道编排（不用 LangChain），完成意图路由、购买标准生成、混合检索、流式推荐、多轮对话与评测闭环。
支持文字 + 图片多模态输入，覆盖美妆/数码/服饰/食品 4 大品类，4 条 Demo 路径全部端到端跑通。

功能描述：
- 设计五阶段 Agent 管道（意图→标准→检索→推荐→决策），阶段间通过依赖注入解耦。意图识别阶段用 7 条确定性规则（正则 + 关键词）拦截 80%+ 的用户输入——预算调整、加购、对比、换一组等固定模式 < 1ms 直接返回结果，仅模糊输入触发 LLM 调用。全链路 asyncio 并发——图片分析与文字意图并行、投机检索与 LLM 标准生成并发。
- SSE 流式推送 10 种结构化事件类型，LLM 等待期间每 0.8s 发一次 thinking 心跳保持连接活性。流式已输出 token 后失败的请求不重试——SSE 场景下重试会导致客户端收到重复文本。模块 import 时自动比对 Python 端事件类型与 contracts/sse-events.schema.json，不一致直接 ImportError 阻止服务启动。
- 意图阶段已拿到品类/预算/肤质等关键约束，不等 LLM 生成完整标准，直接用这些字段构造简化标准先行启动 embedding → pgvector → BM25 → Rerank 全链路，与 LLM 推理时间重叠。LLM 完成后仅需一次 O(n) 内存后过滤对齐约束差异。实测首卡延迟从约 7s 降至约 3s，失败时自动降级为串行路径，可用性不劣化。
- 混合检索五层递进。硬过滤放首层——品类/预算/品牌等刚性条件走 SQL B-tree 索引，不经过向量相似度，避免"200 元预算"语义漂移到 198 元商品。pgvector 1024 维向量召回做语义匹配，BM25 关键词召回弥补向量对专有名词和型号的覆盖不足，两者互补。RRF 融合排名而非原始分数，避免向量分的量级差异淹没关键词信号。Cross-encoder 精排后，每件商品从命中的知识库 chunk 中按证据类型（选购理由/FAQ/风险提示/对比维度）各取一条原文作为推荐依据。严格条件无结果时自动放宽预算（1.3→1.5→无上限），品类不进入放宽逻辑。
- 检索层将推荐理由绑定到数据库 chunk 原文，前端可点开展示来源；生成层对 LLM 输出做 23 项禁止词过滤（库存/运费/优惠券/次日达等不可验证的商业声明）；验证层 GroundingGuard 扫描输出中的价格数字，与数据库真实价格交叉比对，不匹配时注入纠偏标注。
- 本轮未指定的购买标准字段自动从上一轮继承。话题切换判定——品类和产品类型变了就视为新话题，此时品牌和产品约束清零但预算等通用限制保留。用户反馈（like/dislike/排除项）通过 feedbacks 表持久化并注入下轮检索。
- 意图识别/标准生成/推荐解释/视觉理解等任务级接口各自独立配置主备模型，单模型内 3 次重试（仅重试瞬态网络错误，超时不重试），流式已输出部分内容后失败直接终止并返回 error 事件。
